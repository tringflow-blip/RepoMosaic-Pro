     1→# RepoMosaic Pro — Advanced Skill Map Project Worklog
     2→
     3→## Project Overview
     4→
     5→Building an **Advanced Skill Map** dashboard that upgrades the rudimentary regex-based
     6→skill mapping in the original `RepoMosaic-Pro` (https://github.com/tringflow-blip/RepoMosaic-Pro)
     7→to an LLM-powered, multi-dimensional skill attribution system.
     8→
     9→### What the original does (the "rudimentary" part the user wants fixed)
    10→- Detects only 12 hardcoded capability strands (Auth, AI/ML, Frontend, Backend, …) using
    11→  regex pattern matching on file paths and language names.
    12→- Per-person skills = `{ name, score, commits }` derived purely from which repos the person
    13→  touched × the regex-detected capabilities on those repos. No semantic understanding.
    14→
    15→### What we are building (the upgrade)
    16→1. **Flexible LLM integration** — GLM via `z-ai-web-dev-sdk` by default, plus a configurable
    17→   custom OpenAI-compatible endpoint (API key + base URL + model). The user can paste an
    18→   API key in the UI.
    19→2. **Multi-dimensional skill mapping** per chunk of commits:
    20→   - **Sector** (FinTech, DevTools, AI/ML, HealthTech, E-commerce, EduTech, Infra/DevOps, …)
    21→   - **Problem type** (Authentication, Real-time Sync, Vector Search, ETL, Observability, …)
    22→   - **Technical capability** (React, Prisma, WebSockets, RAG, Terraform, …)
    23→   - **Methodology** (TDD, Monorepo, Trunk-based, Microservices, …)
    24→   - **Role** (Architecture, Implementation, DevOps, Docs, QA, …)
    25→3. **Per-committer attribution** — each commit chunk is tagged with the author, so skills
    26→   are attributed to the person who actually committed the code.
    27→4. **GLM used for graph creation** — every chunk of commits is sent to GLM through a
    28→   reusable "skill" prompt; the model returns structured skill tags. The frontend then
    29→   renders a force-graph from the aggregated tags (no LLM in the frontend).
    30→5. **Test target**: https://github.com/Gaia-Recipe/
    31→
    32→### Tech stack
    33→- Next.js 16 (App Router) + TypeScript 5 + Tailwind 4 + shadcn/ui
    34→- `octokit` for GitHub API
    35→- `d3-force` for canvas force-graph
    36→- `z-ai-web-dev-sdk` (GLM) for LLM skill extraction (backend only)
    37→- Prisma + SQLite for scan-result caching
    38→- Single route `/` (per project rules)

   227→## Data-Quality Fix: Tag Normalization
   228→1. **Tag canonicalizer** (`src/lib/analysis/advanced-skill-map.ts`):
   229→   - Added `buildCanonicalizer()` that collapses near-duplicate tag names
   230→     into a single canonical form. Uses three strategies:
   231→     a) An `ALIASES` map for common LLM abbreviations (JS→JavaScript,
   232→        TS→TypeScript, HTML5→HTML, CSS3→CSS, etc.).
   233→     b) Normalized-key grouping: lowercase + strip punctuation → tags that
   234→        normalize to the same key merge, keeping the longest variant as
   235→        canonical (so "Refactoring" beats "Refactor").
   236→     c) Prefix merging: if one normalized key is a prefix (≥4 chars) of
   237→        another, they merge (catches "react"/"reactjs").
   238→   - Added `buildTagCanonicalMap()` that builds a per-dimension resolver
   239→     across all extractions in a scan.
   240→   - The `aggregateSkillMap()` function now pre-normalizes all tags before
   241→     aggregation, so duplicates collapse at both the per-person and org-wide
   242→     rollup levels.
   243→   - Verified: a fresh scan on broccobae-website now shows clean sectors
   244→     ("E-commerce", "Web3/Crypto") with no EduTech/EduCook/EduHealth spam.
