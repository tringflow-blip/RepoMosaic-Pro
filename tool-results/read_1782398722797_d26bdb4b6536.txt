     1→     1→# RepoMosaic Pro — Advanced Skill Map Project Worklog
     2→     2→
     3→     3→## Project Overview
     4→     4→
     5→     5→Building an **Advanced Skill Map** dashboard that upgrades the rudimentary regex-based
     6→     6→skill mapping in the original `RepoMosaic-Pro` (https://github.com/tringflow-blip/RepoMosaic-Pro)
     7→     7→to an LLM-powered, multi-dimensional skill attribution system.
     8→     8→
     9→     9→### What the original does (the "rudimentary" part the user wants fixed)
    10→    10→- Detects only 12 hardcoded capability strands (Auth, AI/ML, Frontend, Backend, …) using
    11→    11→  regex pattern matching on file paths and language names.
    12→    12→- Per-person skills = `{ name, score, commits }` derived purely from which repos the person
    13→    13→  touched × the regex-detected capabilities on those repos. No semantic understanding.
    14→    14→
    15→    15→### What we are building (the upgrade)
    16→    16→1. **Flexible LLM integration** — GLM via `z-ai-web-dev-sdk` by default, plus a configurable
    17→    17→   custom OpenAI-compatible endpoint (API key + base URL + model). The user can paste an
    18→    18→   API key in the UI.
    19→    19→2. **Multi-dimensional skill mapping** per chunk of commits:
    20→    20→   - **Sector** (FinTech, DevTools, AI/ML, HealthTech, E-commerce, EduTech, Infra/DevOps, …)
    21→    21→   - **Problem type** (Authentication, Real-time Sync, Vector Search, ETL, Observability, …)
    22→    22→   - **Technical capability** (React, Prisma, WebSockets, RAG, Terraform, …)
    23→    23→   - **Methodology** (TDD, Monorepo, Trunk-based, Microservices, …)
    24→    24→   - **Role** (Architecture, Implementation, DevOps, Docs, QA, …)
    25→    25→3. **Per-committer attribution** — each commit chunk is tagged with the author, so skills
    26→    26→   are attributed to the person who actually committed the code.
    27→    27→4. **GLM used for graph creation** — every chunk of commits is sent to GLM through a
    28→    28→   reusable "skill" prompt; the model returns structured skill tags. The frontend then
    29→    29→   renders a force-graph from the aggregated tags (no LLM in the frontend).
    30→    30→5. **Test target**: https://github.com/Gaia-Recipe/
    31→    31→
    32→    32→### Tech stack
    33→    33→- Next.js 16 (App Router) + TypeScript 5 + Tailwind 4 + shadcn/ui
    34→    34→- `octokit` for GitHub API
    35→    35→- `d3-force` for canvas force-graph
    36→    36→- `z-ai-web-dev-sdk` (GLM) for LLM skill extraction (backend only)
    37→    37→- Prisma + SQLite for scan-result caching
    38→    38→- Single route `/` (per project rules)

   227→   227→## Data-Quality Fix: Tag Normalization
   228→   228→1. **Tag canonicalizer** (`src/lib/analysis/advanced-skill-map.ts`):
   229→   229→   - Added `buildCanonicalizer()` that collapses near-duplicate tag names
   230→   230→     into a single canonical form. Uses three strategies:
   231→   231→     a) An `ALIASES` map for common LLM abbreviations (JS→JavaScript,
   232→   232→        TS→TypeScript, HTML5→HTML, CSS3→CSS, etc.).
   233→   233→     b) Normalized-key grouping: lowercase + strip punctuation → tags that
   234→   234→        normalize to the same key merge, keeping the longest variant as
   235→   235→        canonical (so "Refactoring" beats "Refactor").
   236→   236→     c) Prefix merging: if one normalized key is a prefix (≥4 chars) of
   237→   237→        another, they merge (catches "react"/"reactjs").
   238→   238→   - Added `buildTagCanonicalMap()` that builds a per-dimension resolver
   239→   239→     across all extractions in a scan.
   240→   240→   - The `aggregateSkillMap()` function now pre-normalizes all tags before
   241→   241→     aggregation, so duplicates collapse at both the per-person and org-wide
   242→   242→     rollup levels.
